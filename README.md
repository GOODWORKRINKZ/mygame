# LED Arcade — консоль на ESP32-C3

Настольная консоль на светодиодной ленте WS2812 (32 светодиода) с тремя играми.
Платформа — **PlatformIO** (Arduino framework).

## Железо

- ESP32-C3 (DevKitM-1 / SuperMini)
- Лента WS2812B × 32
- OLED 0.96" 128×64 SSD1306 (I2C)
- 2 большие кнопки (зелёная = игрок 1, синяя = игрок 2)
- 1 маленькая кнопка (меню)
- Бузер (пассивный или активный)
- Вибромоторчик

## Распиновка (таблица)

| Сигнал             | GPIO ESP32-C3 | Куда паять                                      |
|--------------------|---------------|-------------------------------------------------|
| DATA ленты WS2812  | **2**         | DIN ленты, через резистор 330–470 Ом           |
| OLED SDA           | **4**         | SDA дисплея                                     |
| OLED SCL           | **5**         | SCL дисплея                                     |
| Кнопка P1 (зелёная)| **0**         | кнопка между GPIO0 и GND                        |
| Кнопка P2 (синяя)  | **1**         | кнопка между GPIO1 и GND                        |
| Кнопка MENU        | **3**         | кнопка между GPIO3 и GND                        |
| Бузер              | **7**         | через транзистор (см. схему)                    |
| Вибромотор         | **6**         | через транзистор (см. схему)                    |
| Питание ленты      | 5V / GND      | отдельный источник 5 В, **общий GND обязателен**|

> **Важно про GPIO10:** на некоторых платах ESP32-C3 (DevKitC-02 и т.п.)
> GPIO10 — это встроенный RGB-светодиод. Если при заливке прошивки ты
> видишь, что onboard LED мигает цветами, а внешняя лента молчит —
> переключись на GPIO2 (или любой другой свободный GPIO).

> Все пины меняются в одном месте: `include/config.h`.

> **Не используйте** GPIO2, GPIO8, GPIO9 (страппинг-пины, участвуют в загрузке)
> и GPIO18/19 (USB), GPIO20/21 (UART0) на большинстве плат ESP32-C3.

## Питание ленты (важно!)

32 светодиода WS2812 на полной яркости белым ≈ 32 × 60 мА ≈ **1.9 А**.
Поэтому:

1. Ленту питайте от **внешнего источника 5 В** (не от 3.3 В вывода ESP32 и не от
   его встроенного стабилизатора — он не потянет).
2. **GND ленты, GND питания и GND ESP32 соединяются вместе** (общий провод).
3. Возле ленты на 5V–GND поставьте электролит **470–1000 мкФ**.
4. В разрыв DATA — резистор **330–470 Ом** (защита первого светодиода).
5. В коде яркость ограничена `LED_BRIGHTNESS = 80` (в `config.h`).

## Кнопки

Схема простая: кнопка замыкает GPIO на **GND**, в коде включена внутренняя
подтяжка `INPUT_PULLUP` (к 3.3 В), поэтому внешних резисторов формально не
требуется. Но для надёжности рекомендуется добавить внешние:

```
   3.3V
    │
   [10k]  ← подтяжка (опционально, внутренняя уже есть)
    │
    ├──── GPIO (0 / 1 / 3)
    │
  [кнопка]
    │
   GND
   └──[100nF]── GND   ← опционально, подавление дребезга
```

- Подтяжка: **10 кОм** к 3.3 В (внешняя нужна только если хочется жёстче).
- Конденсатор 100 нФ — по желанию, дребезг и так режется в коде (8 мс).

## Бузер

Пин не может отдавать большой ток (максимум ~20–28 мА на вывод), поэтому
бузер включаем через транзистор **NPN** (S8050, 2N2222, BC547):

```
                          +5V (или 3.3V)
                            │
                       [бузер]
                            │
  GPIO7 ──[1k]──B  NPN     │
                  \ C ─────┘
                   E
                   │
                  GND
```

- Резистор базы: **1 кОм**.
- Для **пассивного** бузера ничего больше не нужно (код генерирует ШИМ-тон).
- Для **активного** бузера (со встроенным генератором) тот же монтаж; тон в
  коде можно игнорировать — он будет просто пищать.

## Вибромоторчик (ваш вариант с 200 Ом)

Мотор напрямую к GPIO подключать **нельзя**: рабочий ток вибромоторчика
60–120 мА, а вывод ESP32 держит ~20 мА. Нужен транзисторный ключ:

```
        +5V (или 3.3V, см. примечание)
         │
   [мотор M]
         │
   [R=200 Ом]   ← ваш ограничитель тока/силы вибрации
         │
  GPIO6 ──[1k]──B  NPN
                  \ C ─────┘
                   E
                   │
                  GND

  + диод 1N4148 / 1N5819 ПАРАЛЛЕЛЬНО мотору:
      катод (полоска) → +5V, анод → коллектор транзистора
```

Обязательные элементы:
- **Транзистор NPN** (S8050 / 2N2222 / BC337) — коммутирует ток мотора.
- **Диод 1N4148 или 1N5819** параллельно мотору (обратный выброс ЭДС при
  выключении!) — катод к плюсу питания.
- **Резистор базы 1 кОм** — ограничивает ток базы
  ((3.3 − 0.7) / 1к ≈ 2.6 мА; при hFE ≥ 50 это до ~130 мА коллектора).

Про резистор **200 Ом** последовательно с мотором:
- Он ограничивает ток и «силу» вибрации: при 5 В питания макс. ток ≈ 5/200 =
  25 мА (без учёта сопротивления мотора — реально меньше). Это щадящий режим.
- Если вибрация слабая — уменьшите до 100 Ом или уберите.
- Питайте мотор от **5 В** (от 3.3 В многие моторчики не стартуют).
- Если мотору нужно больше 25 мА — уменьшайте резистор; транзистор и диод
  остаются в схеме в любом случае.

## Слой логической адресации светодиодов (LUT)

Лента собрана из нескольких панелей, и часть может быть припаяна «задом
наперёд». Чтобы в коде всегда считать, что логический светодиод `0` — крайний
левый, а `31` — крайний правый, используется таблица переадресации
`logical -> physical`. Она строится в `include/led_map.h` из описания панелей:

```cpp
// 4 панели по 8 светодиодов, 2-я панель припаяна наоборот:
static const LedSegment PANELS[] = {
  {  0, 8,  0, false },
  {  8, 8,  8, true  },   // физические 8..15, но идут в обратную сторону
  { 16, 8, 16, false },
  { 24, 8, 24, false },
};
```

Отредактируйте `PANELS` под вашу реальную ленту. После прошивки при старте по
ленте пробегает одиночный светодиод — так удобно проверить, что порядок
правильный.

## Игры и управление

| Кнопка          | Действие                                          |
|-----------------|---------------------------------------------------|
| Зелёная         | игрок 1 (левая сторона)                            |
| Синяя           | игрок 2 (правая сторона)                           |
| Маленькая MENU  | короткое нажатие — переключить игру, удержание ~0.8 с — сброс |

1. **TUG OF WAR (перетягивание)** — игроки быстро жмут каждый свою кнопку,
   змейки ползут от краёв навстречу. Точка встречи сдвигается; кто вытолкнул
   соперника из средней зоны (16 светодиодов в центре) — выиграл раунд.
2. **SHOOTER (стрелялка)** — у каждого база с ХП. Кнопка запускает снаряд;
   свои снаряды при встрече взаимно уничтожаются. Долетел до базы — минус ХП.
3. **PONG (одномерный пинг-понг)** — удерживаешь кнопку: шпингалет копит
   энергию (до 8 пикселей), при отпускании бьёт. Мяч отбивается только во
   время удара; залетел на обратном ходе — гол.

Матч в каждой игре идёт до `ROUNDS_TO_WIN` (3) побед.

## Сборка и прошивка (PlatformIO)

1. Установите PlatformIO (расширение VS Code «PlatformIO IDE» или
   `python -m pip install platformio`).
2. Откройте папку проекта.
3. При необходимости поменяйте `board` в `platformio.ini`:
   - обычная DevKitM-1 — `esp32-c3-devkitm-1` (уже стоит);
   - «SuperMini» — `lolin_c3_mini`.
4. Сборка и прошивка:

```bash
pio run -t upload
```

5. Монитор порта:

```bash
pio device monitor
```

## Настройка под себя

- Пины — `include/config.h`.
- Раскладка панелей ленты (LUT) — `include/led_map.h` (`PANELS`).
- Скорости игр, ХП, яркость, число побед — `include/config.h`.
- Если цвета на ленте «перепутаны» (красный/зелёный) — замените в
  `hardware.h` `NEO_GRB` на `NEO_RGB`.
- Адрес OLED: `OLED_ADDR` в `config.h` (0x3C или 0x3D — код пробует оба).
